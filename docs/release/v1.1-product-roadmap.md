# Recommended Product Roadmap — after v1.0.0 (not started)

**Status:** Recommendation only. **Do not start** until Product Owner approval after RC1 dogfood and v1.0.0.

Per PO Decision 007: prefer dogfood → v1.0.0 before any v1.1 feature work.

---

## Phase 0 — Now (RC1)

1. Tag `v1.0.0-rc1`
2. Use daily with Claude Code for 1–2 weeks
3. Fill RH-002 checklist + dogfood log
4. Fix only stability bugs discovered

## Phase 1 — v1.0.0 GA

- Complete manual QA sign-off
- Windows smoke if claiming Windows support (or mark Windows experimental in notes)
- Icon polish + optional notarization
- Finalize Known Issues for GA
- Tag `v1.0.0`

## Phase 2 — Candidate v1.1 themes (prioritize from dogfood)

| Theme | Rationale |
|--|--|
| Parser robustness / fixture expansion | Highest leverage if format churn hurts trust |
| PATH / onboarding UX for CLI detection | Common first-run friction |
| Notification reliability (modern APIs) | If dogfood shows missed alerts |
| Sleep/wake refresh correctness | If timers misbehave |
| Windows parity fixes | If Windows is in-scope |
| Lightweight usage history (no heavy charts) | Only if users ask during dogfood |
| Accessibility pass | Quality bar |

## Explicitly later (v1.2+)

- Multi-provider
- Multi-account
- Analytics dashboards / rich charts
- Major UI redesign
- Alternate HTTP usage API (unless CLI becomes untenable — new ADR)

## Anti-goals immediately after RC1

- Starting v1.1 features before dogfood ends
- Architecture refactors without ADR + PO approval
- Expanding settings surface “while we harden”
